## Rules

1. Follow the latest explicit user request. The documentation baseline is complete. The latest request authorizes page-by-page, screen-by-screen refinement. Keep each pass bounded and pause for review before moving to the next screen; final homepage approval remains open.
2. Inspect source and existing changes before editing. App root: `evolvethroughai/`; Git root: parent `WEBSITE/`. Keep Nestd and Maa Lakshmi Muchatlu separate.
3. Preserve the umbrella brand and prioritize the flagship. Preserve the 18-module / 14-project / 1-capstone backbone. Original approved detailed curriculum outranks generated summaries; report unavailable sources.
4. Never fabricate prices, durations, availability, contact details, instructor credentials, outcomes, testimonials, repositories, compliance, metrics or deployments. Separate confirmed, proposed, implemented, tested and owner-approved states.
5. Future AWS/applied-AI content and technology services must remain labeled as unfinalized/planned. DevOps knowledge alone does not establish AI engineering capability.
6. Build one bounded feature, preview desktop/mobile behavior, explain what was tested, refine and obtain approval at meaningful milestones. Preserve assets, accessibility, native interaction and reduced motion. Use clear, beginner-friendly explanations.
7. Obtain explicit authorization for destructive changes, Git pushes, public deployment, external account integrations and new business commitments. Existing session authorization applies; do not repeatedly ask for the same permission.
8. For code changes, use project scripts (TypeScript check and build), then relevant browser/keyboard/mobile checks. For documentation-only changes, check links, completeness, accuracy and source preservation; do not install packages or rebuild the app unnecessarily.
9. Update the relevant canonical document when a decision changes. Keep historical notes labeled as history; never silently promote proposals or old assumptions to current facts.
